# Part 1. 취업 문서 작성 가이드

프로그래머 구직에 필요한 문서는 **이력서 · 자기소개서 · 포트폴리오** 세 가지입니다.
이 셋의 중심은 실력을 실물로 증명하는 **포트폴리오**입니다.

```
취업 문서
├─ 1. 이력서          핵심 역량을 한눈에 요약
├─ 2. 자기소개서       직무 적합성을 이야기로 설득
└─ 3. 포트폴리오       실제 구현물로 실력을 증명
    ├─ 3.1 포트폴리오 요약 문서 (전체 개요)
    ├─ 3.2 프로젝트 기술 문서   (→ Part 2에서 상세)
    └─ 3.3 시연 영상          (YouTube / Drive)
```

> 자기소개서는 **원천 소스**를 먼저 만들어 두면, 자사 양식이나 채용 플랫폼
> (잡코리아·사람인 등)의 문항에 맞춰 재조립할 수 있습니다.

## 문서 관리 원칙

취업 준비는 단발성이 아니라 **반복적으로 수정·발전**하는 작업입니다.
피드백(멘토링·첨삭)을 원활히 받으려면 일관된 관리 체계가 중요합니다.

- 모든 문서를 **Google Drive**(또는 Git)에 모아 폴더 구조를 통일합니다.
- 파일명은 `날짜_작성자_문서종류_버전` 형식으로.
  예: `2025-07-01_김재훈_이력서_v1.pdf`
- 최종 제출은 **PDF**. 워드/한글 원본은 내부 백업용으로만 보관합니다.

## 1. 이력서

지원자의 경험·기술·교육 이력을 **1~2페이지**로 요약한 문서입니다.
서류 전형에서 가장 먼저 검토되므로 **"한눈에 핵심 역량 전달"** 이 최우선입니다.

### 구성 항목

- 증명사진
- 기본 정보 (이름, 연락처, GitHub, 블로그 등)
- 학력 및 교육 이수 이력
- 기술 스택 *(별점 금지, 경험 중심)*
- 주요 프로젝트 요약 (핵심 2~3개)
- 경력 / 인턴 / 실습 이력 (있는 경우)
- 자격증, 수상, 기타 활동

### 형식 원칙

- **깔끔하고 여백이 적은 국문 양식** 사용. ([잡코리아 이력서 양식](https://www.jobkorea.co.kr/goodjob/docs/form))
- 정렬·여백·간격을 일관되게.
- 일반 양식과 자유 양식(Notion·홈페이지 등)을 **둘 다** 준비하면 좋습니다.
  본인을 더 잘 표현하는 자유 양식은 강력한 무기가 됩니다.
- **사실 기반 작성.** 졸업/재학/수료 여부는 정확히 명시.
  (예: `졸업 예정(2025.02)`, `재학 중`, `수료`)

### 작성 요령

| 항목 | 지침 |
|---|---|
| **증명사진** | 미용 정리 후 정장 착용, 스튜디오 촬영 권장 |
| **기술 스택** | 점수화(상·중·하, ★) 금지. **경험 중심** 서술 |
| **링크 삽입** | GitHub·블로그·Notion 등. **실제 활동이 없는 링크는 넣지 말 것** |

### 기술 스택: 이렇게 쓰세요

별점은 주관적이라 신뢰를 주지 못합니다. **무엇을 해봤는지**로 증명하세요.

| ❌ 나쁜 예 | ✅ 좋은 예 |
|---|---|
| Unity ★★★ | Unity – FSM 전투 시스템, Data-Driven 구조 설계 경험 |
| C# ★★ | C# – 이벤트 기반 구조, ScriptableObject 설계에 활용 |

**(예시) 경험 기반 기술 스택 표**

| 기술 분야 | 사용 기술 / 툴 | 경험 기반 설명 |
|---|---|---|
| 게임 엔진 | Unity (2019~2022 LTS) | FSM·AI·Wave 시스템 등 핵심 로직 구현 / Addressable 리소스 로딩 최적화 |
| 프로그래밍 언어 | C# | SOLID 기반 클래스 설계 / LINQ·이벤트·델리게이트 활용 모듈화 |
| DI & 아키텍처 | Zenject | DI 컨테이너 기반 모듈화 / Scene별 Installer로 유지보수성 확보 |
| 비동기 처리 | UniTask, Coroutine | UI 비동기 처리 구조 설계 / 리소스 로딩·서버 통신 비동기화 |
| 백엔드 연동 | Firebase, PlayFab | 인증·실시간 DB 구현 / 클라우드 스크립트 사용 |
| 데이터 관리 | ScriptableObject, JSON, CSV | 밸런싱 파라미터 SO 설계 / 외부 테이블 로딩 시스템 |
| 형상 관리 | Git, SourceTree | Git Flow 협업 / 충돌 해결·브랜치 전략 |

### 학력 및 교육

최종 학력 → 최근 이수 과정 순으로 기재합니다.

**(예시) 정규 / 비정규 교육**

| 구분 | 기관 / 과정 | 기간 |
|---|---|---|
| 정규 | 경일대학교 컴퓨터과학 | 2010.03 ~ 2016.02 |
| 비정규 | 경일 게임 IT 아카데미 – Unity 개발자 양성 과정 | 2025.01 ~ 2025.08 |

### 경력 / 프로젝트 요약

- **경력자**: 회사명 · 역할 · 기간 · **성과 중심**으로.
- **신입/학생**: 개발 프로젝트를 요약. 프로젝트명 · 역할 · 주요 기술 · 성과.

**(예시) 경력 요약**

| 프로젝트 (소속) | 기간 | 역할 | 주요 기술 | 핵심 성과 |
|---|---|---|---|---|
| AOS 전략 게임 *(XYZ Studio)* | 2023.03~2025.04 | 클라이언트 리드 | Unity, Addressable, Firebase, Zenject | FSM/AI 설계·최적화 / 배포 시간 20% 단축 |
| 방치형 RPG *(ABC Games)* | 2021.01~2022.12 | 클라이언트 개발 | Unity, UniRx, IAP | 재화·IAP 시스템 구현 / 주간 이벤트 설계 |

**(예시) 프로젝트 요약 (신입/학생)**

| 프로젝트 | 기간 | 역할 | 주요 기술 | 성과 |
|---|---|---|---|---|
| 생존 서바이벌 게임 (팀) | 2024.11~2025.01 | 클라이언트 | Unity, FSM, ScriptableObject | FSM 기반 AI / 자원 생산 시스템 설계 |
| 탑다운 슈팅 (개인) | 2024.08~2024.09 | 전반 개발 | Unity, DOTween | 총기 시스템 / 오브젝트 풀링 최적화 |

### 자격증 / 수상 / 기타

- 실무 무관 자격증은 빼도 무방. 단 **게임잼 수상·경진대회**는 강력한 가산점.
- 활동 이력(동아리·멘토링·커뮤니티), 군 복무 정보 등도 여기에.

```text
정보처리기사 (2022.03 취득)
2024 경일 게임잼 – 우수상 (개발 부문)
```

## 2. 자기소개서

자기소개서는 이력 요약이 아니라, **성격·경험·가치·목표로 "적합한 인재임"을 설득**하는 글입니다.
핵심 전략은 **원천 소스를 먼저 만들고**, 그것을 문항에 맞춰 재조립하는 것입니다.

### 작성 4단계

| 단계 | 설명 |
|---|---|
| 1. 원천 소스 정리 | 자기 서사를 항목별로 깊이 있게 정리 |
| 2. 문항 매핑 | 기업 자소서 문항에 원천 소스를 매칭 |
| 3. 문장 변환 | 소스를 자연스럽고 설득력 있게 재구성 |
| 4. 첨삭·조정 | 불필요한 표현 제거, 논리 점검, 키워드 강화 |

### 원천 소스 구성 템플릿

가능한 한 **구체적 사례와 수치** 중심으로 작성합니다. 불리한 항목은 생략해도 됩니다.

```
자기소개
- 성장 과정 / 성격의 장단점 / 전공 선택(또는 전향)의 계기
경험 (제일 중요)
- 학업·전공 경험 / 프로젝트 경험 / 문제 해결·위기 대처
- 실패와 극복 / 창의적 해결
협업
- 조직 경험 / 팀 프로젝트 / 주도적 해결
목표
- 지원 동기 / 단기(3~5년)·장기 목표 / 커리어 방향성
```

### 핵심 항목별 지침

**성장 과정** — 연대기 나열이 아니라, *"내가 어떻게 이 직무에 맞는 성향으로 자라왔는가"*.
가족 소개·연대기는 지양하고, 현재 직무 역량과 연결되는 성향에 집중합니다.

**성격의 장단점** — 장점은 구체적 사례와 함께. 단점은 **인정 + 극복/보완 방식**을 반드시 동반.
(단점은 안 써도 되지만, 면접에서 거의 100% 질문됩니다.)

**경험 (가장 중요)** — 모든 경험은 **STAR** 흐름으로 서술합니다.

> **Situation(상황) → Task(과제) → Action(행동) → Result(결과)**

- 단순한 노력("밤 새웠다")은 안 됩니다. **구체적 해결 방식과 교훈**이 필요합니다.
- 실패 경험은 실패 자체보다 *실패 → 원인 분석 → 보완 → 재도전 → 교훈* 흐름이 핵심.

**협업** — "나 혼자 잘했다"는 쓰지 마세요. 반드시 **역할 + 행동 + 결과**의 맥락을.

**목표** — 꿈이 아니라 **현실적 계획 + 성장 비전**. 회사·산업 흐름과 방향이 맞으면 설득력이 큽니다.

### 원천 소스 → 문항 변환 예시

| 기업 문항 | 활용 전략 |
|---|---|
| "성격의 장단점을 서술하시오" | `성격의 장단점` 사례 발췌 + 단점은 보완 방법과 연결 |
| "팀 갈등을 해결한 경험" | `협업 경험` 중 커뮤니케이션·조율 중심 경험 선택 |
| "장기 커리어 목표" | `장기 목표` + `커리어 방향성` 연결 |

**(예시) "어려움을 극복한 경험"**

> 팀 프로젝트에서 Fusion 네트워크를 처음 접했을 때, 낯선 동기화 개념과 복잡한 API로
> 큰 어려움을 겪었습니다. 하지만 이 기능이 프로젝트의 핵심이라 판단해 공식 문서와 포럼,
> 샘플을 끊임없이 분석했고, 시행착오 끝에 모든 플레이어가 동일한 상태를 공유하는 멀티플레이를
> 안정적으로 구현했습니다. 이 경험으로 낯선 기술도 끝까지 파고드는 끈기를 키웠습니다.

### 유의사항

- **허위·과장 금지.** 면접에서 구체적으로 파고들면 드러납니다.
- **직무 연관성 우선.** 같은 경험이라도 직무 적합성 높은 사례를 앞세우세요.
- **서사 일관성.** 모든 항목이 같은 방향성(성장/문제해결/협업)을 향해야 글 전체가 흔들리지 않습니다.

## 3. 포트폴리오

프로그래머 역량을 **실제 구현물로 증명하는 가장 핵심 문서**입니다.
자격증보다 훨씬 중요합니다. "할 줄 안다"는 주장이 아니라 **한 결과물**을 보여주세요.

```
포트폴리오
├── 1. 포트폴리오 요약 문서   전체 프로젝트·기술 스택·역할 개요
├── 2. 시연 영상             프로젝트별 링크 (편집본 권장)
└── 3. 프로젝트 상세 문서     기술 문서 (→ Part 2)
```

> 시연 영상과 기술 문서는 **짝을 이뤄** 보여주는 것이 효과적입니다.

### 3.1 포트폴리오 요약 문서

리크루터가 **빠르게 파악**할 수 있도록, 기술 기반 성과 중심으로 구성합니다.

| 항목 | 작성 지침 |
|---|---|
| 이름 / 연락처 | 상단에 명시 |
| 기술 스택 요약 | 단순 나열 금지. 경험 기반 (예: "Unity – FSM 전투 시스템 설계") |
| 대표 프로젝트 | 제목 + 한 줄 설명 + 기술 키워드 + 본인 역할 |
| 협업 경험 | 팀 프로젝트라면 기여도·역할 반드시 분리 명시 |
| 링크 정리 | GitHub · 기술 문서 · 시연 영상 바로가기 |

**(예시) 프로젝트 요약 표**

| 프로젝트명 | 한 줄 소개 | 핵심 기술 | 역할 | 링크 |
|---|---|---|---|---|
| 디펜스 게임 | 실시간 멀티 디펜스 | Unity, Fusion, FSM | 팀 리더 / 네트워크 | GitHub · 기술문서 · 영상 |

### 요약 문서의 두 가지 구성 방식

포트폴리오 요약은 강조점에 따라 두 형태로 나뉩니다. **둘을 혼합**해도 됩니다.

| 방식 | 구성 | 적합한 경우 |
|---|---|---|
| **프로젝트 중심** | 자기소개 → 기술 스택 → 프로젝트 1·2·3 (각 요약) | 완성 프로젝트가 여러 개일 때 |
| **기술 스택 중심** | 자기소개 → 주요 기술 스택별로 관련 프로젝트 연결 | 특정 기술 전문성을 강조할 때 |

### 3.2 프로젝트 상세 문서 (기술 문서)

프로젝트의 개발 과정과 구현을 상세히 설명하는 문서입니다.
단순 구현 설명이 아니라 **"왜 그렇게 만들었는가", "문제를 어떻게 해결했는가"** 가 핵심입니다.

> 작성법은 **Part 2. 기술 문서 작성 가이드**에서 자세히 다룹니다.

### 3.3 시연 영상

핵심 기능을 보여주는 **5분 이내** 영상입니다.

- 기능 설명 + 실제 동작 화면으로 강한 인상을 줍니다.
- UI 흐름 / 전투 시스템 / 구현 흐름 중심으로.
- **편집 원본은 삭제하지 말고 보관**하세요 (수정 대응용).
