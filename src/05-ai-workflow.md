# Part 5. AI 활용 기술문서 워크플로우

Part 2~4에서 **무엇을 쓰고**(기술 문서), **어떻게 보여주고**(레이아웃),
**어떻게 그리는지**(Mermaid)를 배웠습니다. 이 파트는 그 과정을
**웹 기반 AI 챗봇으로 가속**하는 방법입니다.

> **전제**: 복잡한 도구나 설치는 필요 없습니다. **웹 브라우저로 AI 챗봇에 접속해
> 대화하는 수준**이면 충분합니다. 코드나 문서 초안을 만들어 본 적 있으면 바로 따라올 수 있습니다.

## 5-1. 큰 그림: AI는 '초안 생성기'다

AI를 **"내 생각을 빠르게 초안으로 바꿔주는 도구"** 로 이해하세요.
AI가 문서를 대신 써주는 게 아니라, **여러분이 아는 것을 정리하는 속도**를 높여줍니다.

```
[내 머릿속 지식]          [AI의 역할]              [내가 하는 일]
 기능을 만들었고     →   초안·다이어그램 코드   →   검증·수정·이해
 어떻게 동작하는지        빠르게 생성                (← 여기가 실력)
 알고 있다
```

> **가장 중요한 원칙**: AI는 **여러분이 이미 이해한 것**을 정리할 때 가장 강력합니다.
> 이해하지 못한 것을 AI에게 시키면, 이해하지 못한 채로 그럴듯한 결과물만 남습니다.
> (이 위험은 **5-5. 주의점**에서 자세히 다룹니다.)

---

## 5-2. 전체 워크플로우 (5단계)

크래프팅 시스템을 예로, 기술 문서 한 편을 AI와 함께 만드는 흐름입니다.

```
1. 기능 설명하기      →  내가 만든 것을 AI에게 말로 설명
2. 다이어그램 생성    →  Mermaid 코드를 뽑아냄 (Part 4)
3. 문서 초안 생성     →  5단 구조 초안을 받음 (Part 2)
4. 다듬기            →  내 언어로 고치고 '왜'를 채움
5. 이미지 변환        →  슬라이드 삽입용 PNG로 (Part 7)
```

핵심은 **1번(설명)에 힘을 쏟는 것**입니다. 내가 정확히 설명할수록 AI 결과물의 질이 올라갑니다.
설명이 부실하면 AI는 빈칸을 **그럴듯한 상상**으로 채웁니다.

---

## 5-3. 단계별 실전 (크래프팅 예제)

### 1단계 — 기능 설명하기

AI에게 **맥락 → 구성요소 → 동작 순서**를 알려줍니다. 아는 만큼 구체적으로.

> **입력 예시**
> "유니티 C#으로 만든 크래프팅 시스템을 설명할게.
> 플레이어가 재료를 소비해 아이템을 제작하는데, 레시피마다 성공 확률이 있고
> 실패하면 재료를 절반만 소비해. 클래스는 CraftingManager(제작 총괄),
> Inventory(재료 보관), Recipe(레시피 데이터), CraftingUI(입력)가 있고,
> 제작 결과는 이벤트로 UI에 전달돼."

> **팁**: 이 설명은 사실 **Part 0에서 만든 예제 스펙**과 같습니다.
> 여러분도 다이어그램을 뽑기 전에, 시스템을 이렇게 **글로 먼저 정리**해 두면
> 이후 모든 단계가 쉬워집니다.

### 2단계 — 다이어그램 생성하기

1단계 설명을 바탕으로 원하는 다이어그램을 요청합니다.

> **입력 예시**
> "방금 설명한 클래스들의 관계를 Mermaid 클래스 다이어그램으로 그려줘.
> CraftingManager는 ICraftingService 인터페이스를 구현하고, CraftingUI는
> 구현체가 아니라 인터페이스에 의존하게 해줘(DIP)."

AI가 ` ```mermaid ` 코드를 줍니다. 그대로 GitHub md에 붙이면 그림이 됩니다.

> **여러 각도로 요청하세요**: 같은 시스템을 클래스 → 시퀀스 → 상태 → 플로우차트 →
> ER 순으로 각각 요청하면, Part 4의 5종을 모두 얻습니다. 구체적 프롬프트는 **Part 6**에 있습니다.

### 3단계 — 문서 초안 생성하기

기술 문서의 5단 구조로 초안을 요청합니다.

> **입력 예시**
> "이 크래프팅 시스템의 기술 문서를 써줘. 구조는 '개요 → 시스템 구조 → 핵심 기능 →
> 고민과 선택 → 결과 및 배운 점' 순서로. 각 항목에 뭘 채워야 할지 틀을 잡아줘."

AI는 뼈대와 예시 문장을 채워 줍니다. **하지만 이건 어디까지나 '초안'입니다.**

### 4단계 — 다듬기 (가장 중요)

AI 초안을 **내 언어와 실제 경험으로 교체**합니다. 특히 **'왜(Why)'** 는 AI가 채울 수 없습니다.

> **다듬는 관점**
> - AI가 쓴 일반론("성능을 위해 최적화했다")을 **내 구체적 사례**로 교체
>   ("실패 시 재료 100% 소비 버그를 `success ? 1.0f : 0.5f`로 해결")
> - '고민과 선택'의 근거를 **내가 실제로 한 고민**으로 (AI의 추측이 아니라)
> - 틀린 부분 수정 — AI는 그럴듯하게 **틀리기도** 합니다
> - 코드 스니펫이 **내 실제 코드와 일치**하는지 대조

> **왜 4단계가 핵심인가**: 면접관은 문서가 아니라 **여러분**을 뽑습니다.
> AI가 쓴 매끄러운 일반론은 면접 질문 한 번에 무너집니다.
> 반면 서툴어도 **내가 이해한 내용**은 어떤 질문에도 답할 수 있습니다.

### 5단계 — 이미지로 변환하기 (슬라이드용)

GitHub Repo에서는 Mermaid 코드가 자동으로 그림이 되지만,
**Marp 슬라이드나 발표 자료**에는 **이미지(PNG/SVG)** 로 넣어야 합니다.
입문자는 **웹 도구**만으로 충분합니다.

**방법: mermaid.live (설치 불필요)**

1. [mermaid.live](https://mermaid.live) 접속
2. 왼쪽 편집창에 2단계에서 받은 Mermaid 코드 붙여넣기
3. 오른쪽에 그림이 즉시 렌더링됨
4. **Actions → PNG(또는 SVG)** 로 다운로드
5. 다운로드한 이미지를 슬라이드/문서에 삽입

> **투명 배경이 필요하면** SVG로, **간단히 붙이려면** PNG로 받으세요.
> 슬라이드가 어두운 테마면 SVG가 배경에 자연스럽게 얹힙니다.

**(참고) 명령어에 익숙하다면**: `mermaid-cli`(`mmdc`)로 여러 파일을 한 번에 변환할 수 있습니다.
`mmdc -i diagram.mmd -o diagram.png` 형식입니다. 다만 **입문 단계에서는 mermaid.live로 충분**합니다.

## 5-4. 한 장 요약: 문서 한 편 만드는 루프

```
   ┌─────────────────────────────────────────┐
   │  1. 내가 만든 기능을 글로 설명 (스펙 정리)    │
   └───────────────┬─────────────────────────┘
                   ▼
   ┌─────────────────────────────────────────┐
   │  2. AI로 Mermaid 다이어그램 코드 생성        │
   │  3. AI로 5단 구조 문서 초안 생성            │
   └───────────────┬─────────────────────────┘
                   ▼
   ┌─────────────────────────────────────────┐
   │  4. 내 언어·경험·'왜'로 다듬기 (실력 구간)    │ ★
   └───────────────┬─────────────────────────┘
                   ▼
   ┌─────────────────────────────────────────┐
   │  5. mermaid.live로 이미지화 → 슬라이드 삽입  │
   └─────────────────────────────────────────┘
```

★ 표시한 **4번이 여러분의 실력이 드러나는 구간**입니다. 1·5번은 AI와 도구가 돕지만,
4번은 오직 여러분만 할 수 있습니다.

## 5-5. 주의점: AI가 만든 것을 '내 것'으로

AI는 강력한 초안 생성기지만, **그대로 제출하면 독**이 됩니다.
이 가이드의 철학(Part 2)과 정면으로 연결되는 부분이라, 따로 강조합니다.

### ① "이해 없이 복붙"이 가장 위험하다

> Part 2에서 말했듯, 기술 문서의 목적은 *"코드를 짤 줄 안다"* 가 아니라
> *"내 코드를 남에게 설명할 줄 안다"* 를 보여주는 것입니다.

AI가 만든 다이어그램·코드·문장을 **이해하지 못한 채** 넣으면, 면접에서 정확히 그 지점이
무너집니다. 면접관은 문서를 보고 질문합니다 — *"여기 이 이벤트는 왜 쓰셨어요?"*
이때 "AI가 그렇게 써줘서요"라고 답할 수는 없습니다.

**규칙**: 문서에 들어가는 모든 문장·코드·다이어그램은 **내가 설명할 수 있어야** 합니다.
설명 못 하는 건 넣지 마세요.

### ② AI는 그럴듯하게 '틀린다'

AI는 사실이 아닌 것도 **자신 있게** 말합니다(환각). 특히:

- **존재하지 않는 API·메서드**를 지어내기도 합니다.
- 여러분이 설명 안 한 부분을 **임의로 상상**해 채웁니다.
- 최신이 아닌, **오래된 방식**을 제안하기도 합니다.

**규칙**: 코드는 **실제 프로젝트에서 컴파일·실행**해 확인하고, 다이어그램은
**내 실제 구조와 일치**하는지 대조하세요. AI 출력은 '정답'이 아니라 '검토 대상'입니다.

### ③ '고민과 선택'은 AI가 대신 못 한다

기술 문서에서 가장 중요한 **'왜(Why)'** 는 여러분의 실제 의사결정 기록입니다.
AI에게 "고민과 선택을 써줘"라고 하면 **그럴듯한 일반론**을 만들지만,
그건 여러분이 실제로 한 고민이 아닙니다.

**규칙**: 대안 비교와 최종 결정의 근거는 **내가 실제로 겪은 것**으로 채우세요.
AI에게는 "내가 이러이러하게 고민했는데, 이걸 문장으로 다듬어줘" 정도로만 시킵니다.

### ④ 저작권·정보 보호

- 회사·팀 프로젝트의 코드를 AI에 붙여넣기 전, **공개 가능한 정보인지** 확인하세요.
- 학원·팀의 **비공개 자료**를 무심코 입력하지 않도록 주의합니다.

### 핵심 한 줄

> **AI로 속도를 얻되, 이해로 실력을 증명하라.**
> AI는 여러분을 대체하는 게 아니라, 여러분이 이해한 것을 빠르게 정리하는 조수입니다.

---

## Part 5 정리

- AI는 **초안 생성기** — 내가 이해한 것을 빠르게 정리할 때 가장 강력합니다.
- 워크플로우 5단계: **설명 → 다이어그램 → 문서 초안 → 다듬기 → 이미지화**.
- **다듬기(4단계)** 가 실력 구간. '왜'는 AI가 못 채웁니다.
- 이미지 변환은 **mermaid.live** 클릭만으로 충분(입문자).
- 무엇보다 **이해 없이 복붙 금지** — 넣는 모든 것을 설명할 수 있어야 합니다.
- 다음 파트(Part 6)에서 이 워크플로우에 쓸 **구체적인 한글 프롬프트**를 모아 제공합니다.
